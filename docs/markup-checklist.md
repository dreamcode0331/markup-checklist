# 마크업 품질 체크리스트

퍼블리싱 전 아래 항목을 기준으로 HTML을 검수한다.
항목을 위반하거나 누락된 경우 수정 방향을 함께 제안할 것.

- 기준 출처: marketplace `markup-rules-review`(정적 소스 검수), `markup-a11y`(WCAG 2.2 AA 런타임 접근성, KWCAG 2.2 병기)
- 프로젝트에 `.claude/rules/`가 있으면 그 컨벤션을 우선 적용한다. 없으면 아래 일반 기준으로 판정하고 그 사실을 표기한다.
- 접근성 항목 끝의 `WCAG x.x.x / KWCAG x.x.x`는 `markup-a11y`의 WCAG 2.2 ↔ KWCAG 2.2 매핑을 따른다. KWCAG 대응은 의미 기준 근사 매핑이므로 인증 심사용으로 쓰기 전에 공식 지침으로 다시 확인한다.
- 우선순위 표기: 🔴 필수 · 🟡 권장 · 🟢 선택 (체크리스트 UI의 필수/권장/선택과 같다)
- 항목 앞의 id(`s01`, `a13` 등)는 체크리스트 UI의 항목 id와 같다. 결과 JSON은 이 id로 기록한다.

## HTML 구조

- [ ] s01 🔴 `<!DOCTYPE html>` 선언이 문서 최상단에 위치하는가 — 공통 head include 시 include 파일에서 확인
- [ ] s02 🔴 `<html lang="ko">` 언어 속성이 설정되었는가
- [ ] s03 🔴 `<meta charset="UTF-8">`이 head 내 최상단에 위치하는가
- [ ] s04 🔴 `<meta name="viewport" content="width=device-width, initial-scale=1.0">` 뷰포트 설정이 되었는가
- [ ] s05 🔴 시맨틱 태그(`header`, `nav`, `main`, `section`, `article`, `aside`, `footer`)를 적절히 사용하였는가
- [ ] s06 🔴 헤딩 태그(h1~h6)가 올바른 계층 구조인가 — h1은 페이지당 1개, 레벨 건너뛰기 금지
- [ ] s07 🟡 W3C Validator 검사를 통과하는가 — 중복 `id`, 잘못된 요소 중첩 등 마크업 오류 없음 (KWCAG 8.1.1)
- [ ] s08 🟡 불필요한 `div`/`span` 남용이 없는가 — 의미 없는 래퍼 최소화
- [ ] s09 🟡 기존 컴포넌트/include를 재사용하는가 — 같은 UI 직접 재구현 금지

## 웹 접근성

- [ ] a01 🔴 모든 `<img>`에 `alt` 속성이 있는가 — 장식 이미지는 `alt=""`, 의미 있는 이미지는 목적 전달(파일명·"이미지" 금지) — WCAG 1.1.1 / KWCAG 5.1.1
- [ ] a02 🔴 건너뛰기 링크(Skip Navigation)가 있는가 — WCAG 2.4.1 / KWCAG 6.4.1
- [ ] a03 🔴 키보드만으로 모든 기능을 사용할 수 있는가 — Tab, Enter, Space, Esc / 키보드 트랩·도달 불가 없음, 탭 순서 논리적 — WCAG 2.1.1·2.1.2·2.4.3 / KWCAG 6.1.1·6.1.2
- [ ] a04 🔴 포커스 표시(focus indicator)가 보이는가 — `outline` 제거 시 대체 스타일 제공, hover/focus 상태 대비 유지 — WCAG 2.4.7·1.4.11 / KWCAG 6.1.2
- [ ] a05 🔴 폼 요소에 `<label>`이 연결되었는가 — `for`/`id` 또는 `aria-label`, 오류 메시지는 `aria-describedby`로 연결 — WCAG 1.3.1·3.3.2 / KWCAG 7.3.2
- [ ] a06 🔴 색상 대비(Contrast Ratio)가 충분한가 — 텍스트 4.5:1, 비텍스트(UI 컴포넌트·아이콘) 3:1 이상 — WCAG 1.4.3·1.4.11 / KWCAG 5.4.3
- [ ] a07 🟡 ARIA 속성이 올바르게 사용되었는가 — `role`↔`aria-*` 정합, `aria-controls`/`aria-labelledby` 대상 `id` 실재, 위젯 상태값(`aria-expanded`·`aria-selected`·`aria-valuenow` 등) 제공 — WCAG 4.1.2 / KWCAG 8.2.1
- [ ] a08 🔴 데이터 테이블에 `<caption>`과 `<th scope>`가 있는가 — 카드형 UI는 해당 없음 — WCAG 1.3.1 / KWCAG 5.3.1
- [ ] a09 🟡 링크 텍스트가 명확한가 — "여기를 클릭"·"더보기" 대신 목적지를 알 수 있는 텍스트(또는 blind 텍스트) — WCAG 2.4.4 / KWCAG 6.4.3
- [ ] a10 🟡 새 창 링크(`target="_blank"`)에 안내가 있는가 — `title` 또는 blind 텍스트 — KWCAG 7.2.1
- [ ] a11 🔴 자동 재생 콘텐츠에 정지 수단이 있는가 — 5초 넘게 움직이면 정지/일시정지 제공, 키보드 조작 가능 — WCAG 2.2.2·1.4.2 / KWCAG 6.2.2·5.4.2
- [ ] a12 🟢 WAI-ARIA 랜드마크(`banner`, `navigation`, `main`, `contentinfo`)가 적절히 사용되었는가 — WCAG 1.3.1·2.4.1
- [ ] a13 🔴 아이콘 전용 버튼/링크에 접근성 이름이 있는가 — blind 텍스트 또는 `aria-label`, 일관 적용 — WCAG 4.1.2 / KWCAG 8.2.1
- [ ] a14 🟡 포커스된 요소가 sticky 헤더·배너 등에 가려지지 않는가 — `scroll-padding` 등으로 대응 — WCAG 2.4.11 / KWCAG 6.1.2
- [ ] a15 🔴 클릭/터치 타깃이 24×24px 이상인가 — WCAG 2.5.8 / KWCAG 6.1.3
- [ ] a16 🔴 200% 확대·텍스트 간격 조정 시 콘텐츠가 잘리거나 겹치지 않는가 — WCAG 1.4.4·1.4.12
- [ ] a17 🔴 다이얼로그/아코디언의 포커스를 관리하는가 — 열림 시 포커스 이동, Esc 닫힘, 닫힘 후 트리거로 복귀 — WCAG 2.4.3·2.1.2 / KWCAG 6.1.2
- [ ] a18 🔴 색만으로 정보(필수 항목·오류·선택 상태)를 구분하지 않는가 — WCAG 1.4.1 / KWCAG 5.4.1
- [ ] a19 🟡 상태 메시지를 `role="status"`/`aria-live`로 전달하는가 — WCAG 4.1.3
- [ ] a20 🟡 드래그·멀티터치·경로 제스처에 단일 포인터 대안(버튼·클릭)이 있는가 — 동작은 up/click 시점에 실행 — WCAG 2.5.1·2.5.2·2.5.7 / KWCAG 6.5.1·6.5.2
- [ ] a21 🔴 영상·음성 콘텐츠에 자막이나 대본이 있는가 — 음성 없는 정보 영상은 설명 제공, 미디어가 없으면 해당 없음 — WCAG 1.2.1~1.2.5 / KWCAG 5.2.1
- [ ] a22 🔴 초당 3회 넘게 번쩍이는 콘텐츠가 없는가 — WCAG 2.3.1 / KWCAG 6.3.1
- [ ] a23 🔴 모양·위치·색에만 의존하는 지시가 없는가 — "오른쪽 빨간 버튼" 대신 텍스트로 대상 안내 — WCAG 1.3.3 / KWCAG 5.3.3
- [ ] a24 🔴 포커스·값 변경만으로 새 창·페이지 이동·제출이 일어나지 않는가 — select 변경 즉시 이동 금지 — WCAG 3.2.1·3.2.2 / KWCAG 7.2.1
- [ ] a25 🔴 입력 오류를 텍스트로 알리고 수정 방법을 제시하는가 — 폼이 없으면 해당 없음 — WCAG 3.3.1·3.3.3 / KWCAG 7.3.1
- [ ] a26 🟡 hover/focus로 나타나는 콘텐츠(툴팁·메뉴)를 제어할 수 있는가 — Esc로 닫힘, 포인터를 올려도 유지, 스스로 사라지지 않음 — WCAG 1.4.13
- [ ] a27 🟡 보이는 레이블이 접근성 이름에 포함되는가 — 화면 텍스트와 `aria-label` 불일치 금지 — WCAG 2.5.3 / KWCAG 6.5.3
- [ ] a28 🟡 입력 부담을 줄이도록 구성했는가 — 개인정보 필드 `autocomplete`, 로그인 붙여넣기·자동완성 허용, 같은 절차 내 중복 입력 없음 — WCAG 1.3.5·3.3.7·3.3.8 / KWCAG 7.3.3·7.3.4
- [ ] a29 🟡 시간 제한이 있으면 연장·해제 수단을 제공하는가 — WCAG 2.2.1 / KWCAG 6.2.1
- [ ] a30 🟢 이웃한 콘텐츠가 테두리·간격·배경 등으로 구분되는가 — KWCAG 5.4.4
- [ ] a31 🟢 도움말 수단(고객센터·챗봇·FAQ)이 여러 페이지에서 같은 위치에 있는가 — 단일 컴포넌트 검수면 해당 없음 — WCAG 3.2.6 / KWCAG 7.2.2

## 검수 원칙

### 단정 금지 (최우선)

- 검증 가능한 주장은 반드시 해당 파일을 Read/Grep으로 확인한 뒤 보고한다. 근거를 확인하지 못했으면 결함이 아니라 **확인 필요**로 둔다.
- 규칙과 코드가 어긋나면 코드가 기준일 수 있으므로 단정하지 말고 "규칙 vs 코드 불일치"로 표시한다.

### 스코프 제외 — 참고로 분리

아래는 결함이라도 **참고**로만 보고한다(판정 영향 없음).

- 개발 책임 영역: 이벤트 핸들러, 데이터 바인딩, `aria-disabled` 클릭 차단, 상태/API 연동 등 동작 구현
- 검수용 데모 영역: `<!-- S : [D] … 개발 제외 -->` ~ `<!-- E : [D] … -->` 사이의 데모/caseview/데모 `<script>` 블록

### 전역 컨벤션 구분

"속성/패턴의 부재·혼용"이 후보면 판정 전에 Grep으로 전역 현황을 확인한다.

- 전역에 퍼져 있어 페이지 단독으로 고치면 깨지거나 불일치가 생기면 **전역 컨벤션**으로 분리한다. 표준이 정해진 위반이면 "전역 일괄 적용 필요", 미정·혼용이면 "팀 협의 필요".
- 전역에서 이미 통용되는데 이 페이지만 누락했으면 정상 **수정 필요**다.
- 레거시 현황은 면제 사유가 아니다. 이번 변경분에서 새로 작성·수정한 코드가 만든 위반은 같은 패턴이 레거시에 퍼져 있어도 **수정 필요**로 낸다.

### 소스만으로 판정할 수 없는 항목

크로스브라우징, LCP, 반응형 렌더링, 런타임 접근성(키보드 순회, 포커스 가려짐, 타깃 크기, 확대·텍스트 간격, 다이얼로그 포커스 관리 등), 수동 확인 접근성(자막, 번쩍임, 감각적 지시, hover 콘텐츠, 시간 제한, 도움말 위치 등)은 소스로 단정하지 않는다. 소스에서 위반이 확인되면 수정 필요로 내고, 그렇지 않으면 **확인 필요**로 두고 담당 검수를 적는다.

- 런타임 접근성: `markup-a11y:a11y-audit`
- 수동 확인 접근성: `markup-a11y:a11y-audit` 수동 체크리스트(`references/manual-checklist.md`)
- 레이아웃 깨짐·반응형 렌더: `markup-visual-qa:qa-visual-tester`
- 성능·minify·크로스브라우징: 빌드/QA 단계

## 검수 결과 출력 규칙

HTML 검수 요청 시 반드시 아래 형식으로 결과를 출력한다. 임의로 형식을 변경하지 않는다.

### 통과 기준

- **수정 필요 0건이면 통과**, 1건 이상이면 미통과
- 전역 컨벤션·참고·확인 필요는 판정에 영향이 없다 (목적은 점수가 아니라 "고칠 목록")

### 심각도

- 🔴 높음: 접근성 차단·기능 결함
- 🟡 중간: 컨벤션 위반·잠재 결함
- 🟢 낮음: 사소한 문제·문구·정리
- 기본값은 항목의 우선순위 표기를 따르되, 근거가 있으면 조정한다.

### 출력 형식

반드시 코드블록 안에 아래 템플릿대로 출력한다. 표는 쓰지 않고 목록으로만 쓴다.

```
■ 마크업 검수 결과 — {검수 대상 파일명}

검수일: {YYYY-MM-DD} · 기준: 마크업 품질 체크리스트 v2.0
결과 파일: qa-results/checklist/{검수 대상 파일명}-{YYYYMMDD}.json

[종합] 결과 ✅통과/❌미통과 · 수정 필요 [n] · 전역 컨벤션 [p] · 참고 [k] · 확인 필요 [m]

[카테고리별]  (없으면 '이상 없음')
- HTML 구조 : 이상 없음
- 웹 접근성 : 수정 필요 1
- SEO : 이상 없음
- 성능 최적화 : 확인 필요 2
- 크로스브라우징 : 확인 필요 7
- 반응형 웹 : 이상 없음
- 디자인 토큰·SCSS : 수정 필요 1
- 다국어·리전 : 이상 없음
- 코드 품질 : 이상 없음

[수정 필요]
- 🔴 {항목} → {수정 방향}  (file:line)
- 🟡 {항목} → {수정 방향}  (file:line)

[걸러진 후보 — 단정 금지]
- {후보} → 제외/확인 필요  ({근거 file:line})

[확인 필요 — 런타임·빌드 단계]
- {항목} → {담당 검수: a11y-audit / qa-visual-tester / 빌드 단계}

[전역 컨벤션 — 페이지 단독 수정 불가]
- {패턴} (file:line) → 전역 Grep {n}회 → 일괄 적용 / 팀 협의

[참고 — 개발/데모 영역]
- {항목} (file:line) → 개발 책임 / 검수용 데모
```

### 출력 규칙

1. 후보가 없는 섹션은 생략한다.
2. "해당 없음" 항목(예: 테이블이 없는 페이지의 테이블 항목)은 이상 없음으로 처리하고 따로 나열하지 않는다.
3. 수정 필요 항목에는 반드시 `→` 뒤에 수정 방향을 한 줄로 작성한다.
4. CSS 파일 등 별도 확인이 필요한 항목은 "— SCSS 확인 필요" 등으로 표기한다.
5. 코드블록 바깥에 추가 설명을 붙이지 않는다. 결과만 출력한다.

### 결과 JSON 저장

보고서를 출력할 때 아래 형식의 결과 JSON을 `qa-results/checklist/{검수 대상 파일명}-{YYYYMMDD}.json`에 함께 저장한다. 체크리스트 UI가 이 파일을 불러와 항목을 자동으로 체크한다.

```json
{
  "version": "2.0",
  "file": "index.html",
  "date": "2026-10-26",
  "items": { "s01": "pass", "a08": "na", "a13": "fail", "c01": "check" },
  "notes": {
    "a13": "아이콘 버튼에 aria-label 추가 (index.html:54)",
    "c01": "qa-visual-tester로 확인"
  }
}
```

1. `items`에는 체크리스트의 모든 id를 빠짐없이 넣는다.
2. 상태값은 보고서 판정과 같게 매핑한다.
   - `fail`: 수정 필요
   - `check`: 확인 필요
   - `na`: 해당 없음
   - `pass`: 그 외 (통과)
3. 전역 컨벤션·참고 항목은 판정에 영향이 없으므로 `pass`로 기록하고, 그 내용은 `notes`에 적는다.
4. `fail` 항목에는 `notes`에 수정 방향과 `file:line`을, `check` 항목에는 담당 검수를 반드시 적는다.

### 체크리스트 UI 사용 흐름

1. **AI 결과 불러오기**로 결과 JSON을 넣는다. `pass`·`na` 항목은 자동으로 체크되고, `fail`·`check` 항목에는 배지와 사유가 표시된다.
2. **확인 필요** 항목을 직접 확인하고 체크한다.
3. **내보내기**를 누르면 위와 같은 형식의 보고서가 만들어진다. 체크하지 않은 항목은 수정 필요로, AI가 확인 필요로 남긴 항목은 확인 필요로 집계한다.

## 사용 방법

Claude Code에서 이 파일을 참조하려면 `CLAUDE.md`에 아래 한 줄을 추가한다.

```md
@./docs/markup-checklist.md
```

특정 파일 타입(HTML, Nunjucks 등)에서만 적용하려면 파일 상단에 아래 프론트매터를 추가한다.

```md
---
paths:
  - "**/*.html"
  - "**/*.njk"
---
```
